# Skill: outline-chapter（章纲生成）

## 目标

把「作品设定 + 前文 + 作者本章要求」转成一份**可执行、可校验**的章纲。
章纲是后续正文生成的唯一剧本。它写得含糊，正文必然注水。

## 输入

- 【作品设定】：题材、核心设定、主线
- 【风格样本】：作者的文风样例（只用于判断节奏与语感，不影响情节）
- 【人物档案】：含每个角色的目标、已知信息、行为约束
- 【未回收线索】：明线/支线/伏笔及其状态
- 【前文结尾】：上一章最后约 800 字
- 【本章要求】：作者对本章的额外指令（可能为空）

## 推理步骤（必须按序执行，不要跳步）

1. **定位节奏位**：本章在卷内处于哪个位置——铺垫 / 冲突升级 / 高潮 / 收束 / 转场。
   连续两章同一位阶就是节奏事故。
2. **锁定单一核心事件**：一章只解决一件事。塞进两个核心事件，两个都会滑过去。
3. **选择线索操作**：从【未回收线索】中选 0~2 条推进，或新埋 1 条伏笔。
   优先回收"计划回收章"已过期的线索，否则读者会觉得作者忘了。
4. **拆 beat**：4~7 个。每个 beat 必须写成「谁做了什么 → 导致什么变化」，
   禁止写成"气氛变得紧张"这类无法执行的情绪描述。
5. **设计章末钩子**：必须是信息差或悬念升级。
   "然后他回去睡了"不是钩子，是断更理由。

## 输出契约

只输出一个 JSON 对象，字段名与类型严格如下，不得增删字段、不得加 markdown 代码块：

```json
{
  "title": "章节标题，6~14 字，不含'第X章'",
  "coreEvent": "本章唯一核心事件，一句话",
  "beats": ["beat1", "beat2", "beat3", "beat4"],
  "characters": ["本章出场角色名"],
  "threadsToPlant": ["本章新埋的伏笔，一句话一条，可为空数组"],
  "threadsToPayoff": ["本章回收的已有线索标题，必须与【未回收线索】中的标题逐字一致"],
  "emotion": "本章情绪曲线，如：压抑 → 试探 → 爆发",
  "hook": "章末钩子，一句话",
  "targetWords": 2600,
  "assumptions": ["信息不足时做出的最小假设，可为空数组"]
}
```

字段约束：

| 字段 | 约束 |
|---|---|
| `beats` | 4~7 条 |
| `characters` | 只能来自【人物档案】；需要新角色必须写进 `assumptions` |
| `threadsToPayoff` | 必须逐字匹配已有线索标题 |
| `targetWords` | 整数，2000~4000 |

## 自检（输出前逐条过一遍）

- [ ] 核心事件只有一个，能一句话说清
- [ ] 每个 beat 都有动作和结果，没有纯情绪描述
- [ ] `characters` 全部在人物档案中存在
- [ ] `threadsToPayoff` 的标题能在线索表里找到
- [ ] 章末钩子制造了信息差或风险升级
- [ ] 没有出现"主角突然想到"这类无信息增量桥段
